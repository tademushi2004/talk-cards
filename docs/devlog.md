# 開発記録：トークテーマカード（記事執筆用メモ）

このファイルは、技術ブログ（Zenn / Qiita）を書くための素材です。経緯・設計判断・使い方・実装を、作業しながら追記しています。v1（最初の版）と v2（カードUIへの作り直し）の両方の記録を残しています。

## 1. 作ることになった経緯
- 研究室の飲み会があり、初対面の3回生とも話す必要がある。話題を事前に準備しておきたい。
- 『超人脈術』（メンタリストDaiGo氏の著書。著者表記は執筆時に書籍で確認）で、「誰とでも親密になれる36の質問」を知った。これを、カードを引くようにトークテーマにできる簡単なWebアプリにしたい。
- 追加で、『最強のコミュ力の作り方』が紹介するディープトークの定番質問10問も取り込む。ユーザーのメモでは著者は「鈴木雄」氏だが、「鈴木祐」氏の可能性がある。書名の表記（「作り方」か「つくりかた」か）とあわせて、執筆前に書籍で確認する。
- 2冊とも、カリスマ性や人脈を作る方法としてディープトークを紹介している。

## 2. 参考資料と出典の扱い
### 36の質問：原典から直接引用する（v2で変更）
- 孫引きを避けるため、出典を本ではなく原論文にした。
  - Aron, A., Melinat, E., Aron, E. N., Vallone, R. D., & Bator, R. J. (1997). The experimental generation of interpersonal closeness: A procedure and some preliminary findings. *Personality and Social Psychology Bulletin*, 23(4), 363–377.
  - 36問はこの論文の付録にあり、Set I・II・III の3組（各12問）に分かれ、後になるほど踏み込んだ内容になる。
- 質問文は英語原文をもとに独自に日本語訳した。v1では本の日本語版を言い換えていたが、原典と意味がずれている箇所があった。
  - Q33: 原典は「誰とも連絡が取れないまま今夜死ぬとしたら、伝えておかなかったことで一番後悔するのは何か。なぜまだ伝えていないのか」。本では後半の問いが抜け、「誰に何を伝えたかったか」になっていた。
  - Q19「1年後に突然死ぬと分かったら、今の生き方の何かを変えるか」、Q23「家族はどれくらい親密で温かいか」、Q26「〜を分かち合える人がいたらいいのに」、Q31「もうすでに好きだと思っているところ」なども原文に合わせた。
- 本の紹介と、確認できた事実の違い（記事で書くときの注意）
  - 論文の年: 本は1996年と書くが、正しくは1997年。
  - 「最後に4分間見つめ合う」は、2015年のNew York Timesのエッセイ（Mandy Len Catron "To Fall in Love With Anyone, Do This"）で広く知られた手順。原論文の手続きに含まれるかは、論文本文で確認してから書く。
  - 結婚の件は、報道では「半年後に参加者2人が結婚した」と紹介されている（The Guardian の記事が APS のサイトで紹介）。
  - 参加者「33人」という本の記述は未確認。
- 参考にしたWebページ: UC Berkeley Greater Good Science Center「36 Questions for Increasing Closeness」（36問の原文と、Set ごとに時間を3等分する進め方）。

### ディープトーク定番の質問
- 本の著者が「過去のディープトーク研究で使われた定番の質問」として紹介したもの。詳細な出典は第4章の参考文献5・6。
  - 参考文献6: Kardas, Kumar & Epley (2022) *Overly shallow?: Miscalibrated expectations create a barrier to deeper conversation*。ディープトーク研究。
  - 参考文献5: Antonakis & Day (2018) *The nature of leadership*。リーダーシップ研究の教科書で、質問リストの出典ではないと判断した。
- 10問が論文で実際に使われた質問かは未確認。そのため記事では「本の著者が紹介した定番質問」と書き、「効果が高いと確認された」とは断定しない。質問文は言い換え。

## 3. 設計の決定事項
### データ
- 全44枚: 36問と追加8枚。「恥ずかしかった経験」はQ29に、「死について」はQ7・19・33に内容が近いため統合した。
- 項目（タグ）
  - `level`: 軽め(1) / 中間(2) / 深め(3)。36問は原典の Set I・II・III と一致させた。追加8枚は仮置きで、軽め3・中間5。
  - `set`: 原典の Set 番号（v2で追加）。カードに「Aron et al. (1997) Set II・Q14」のように出典を表示する。
  - `heavy`: 重め。死・家族・つらい記憶などの9枚（Q7, 18, 19, 23, 24, 32, 33, 35, 36）。
  - `kind`: 質問 / 作業。作業型は8枚（Q8, 11, 22, 25, 26, 28, 31, 36）で、説明（hint）を表示する。
  - `source`: `aron1997` / `suzuki`。v1 の `aron36` から名前を変え、保存済みの設定は読み込み時に読み替える。
  - `deeptalk`: 「ディープトーク定番」バッジ（追加8枚）。
- 飲み会向けの調整: Q11の「4分間」を「1分くらい」にし、Q22・28・31は「隣の人に」と説明を添えた。

### v2：カードを引く手触り（UI/UXの作り直し）
- 作り直した理由: v1は色弱への配慮などはよかったが、カードを引くワクワク感がなかった。画面に対してカードも小さかった。主にスマートフォンで使う前提で、本物のカードを引くような手触りを足す。
- 採用した案（A〜D、F、H）。不採用はレア演出、Set順に深まるモード、振動・効果音。
  - A. 大きなカードと山札: カードは画面幅の約88%、トランプに近い5:7の比率。フィルターは「設定」ボタンで開く下からのシートにしまい、画面は「山札とカード」だけにした。
  - B. 裏向きで出て、めくる: 山札から引いたカードは裏向きで、タップすると3Dで裏返る（`rotateY` と `backface-visibility`）。
  - C. スワイプ: 山札を上にスワイプすると引ける。表のカードは左右にフリックして捨てる。指に追従して傾き、勢いが足りなければ元の位置に戻る。ボタン操作とキーボード（PC）も残した。
  - D. 段階ごとの裏面: 軽め＝緑・ドット・○、中間＝琥珀・斜線・△、深め＝紫・ひし形・◇。色、模様、記号、文字の4つで区別するので、色だけに頼らない。裏の時点で次のカードの段階が分かり、「深めが来た…」という緊張感が出る。
  - F. 山札の厚み: 残り枚数に比例して重なり（最大6枚）を描く。1周するとシャッフルのアニメーションと「2周目」の通知が出る。
  - H. 話した／パス: 右へフリックで「話した」、左へで「パス」。スワイプ中は「✓ 話した」「✕ パス」のスタンプが文字で浮かぶ。記録は「今夜の記録」シートで一覧でき、消去は2回押しで確定する。
- 「戻す」ボタン（取り消し）
  - 山札の一番上が見えている状態では、最後に捨てたカードを表向きで手元に戻す。
  - カードが手元にある状態では、そのカードを山札の一番上に戻し、1つ前のカードを手元に戻す。
  - どちらの場合も、記録の最後の1件を取り消す。
- その他
  - スマホの全画面レイアウトにした（`100dvh`、ノッチ付近の余白 `safe-area-inset`）。カード上ではスクロールや引っ張って更新を止める（`touch-action: none`、`overscroll-behavior: none`）。
  - 裏向きの間は、読み上げソフトが質問文を読まないようにした（`aria-hidden`）。
  - 「動きを減らす」設定の端末では、アニメーションを最小にする。

### 技術
- 外部ライブラリなし。ファイルは `index.html` / `style.css` / `questions.js` / `gesture.js` / `app.js` の5つ。
  - データを JSON ファイルにしないのは、`index.html` をローカルで直接開く（file://）と fetch が失敗するため。`questions.js` に置けば、ローカルでも GitHub Pages でも同じに動く。
- 設定と記録は localStorage に保存する（`talkcards.settings.v2` / `talkcards.log.v1`）。
- 公開は GitHub Pages を想定。ローカルで `index.html` を開いても使える。

## 4. 使い方
1. `index.html` を開く（初期状態は「重めを除く」がON）。必要なら「設定」で段階や出典を絞り込む。
2. 山札を上にスワイプ（またはタップ）して1枚引き、タップしてめくる。
3. 質問を隣の人に投げかける。作業型のカードは、下の説明に従って進める。
4. 話し終えたら右へスワイプ（話した）、気が乗らなければ左へスワイプ（パス）。ボタンでも操作できる。
5. 間違えたら「戻す」。「記録」で、その夜に話したカードを振り返れる。
6. PCではキーボードでも操作できる。↑またはスペースで引く・めくる、→で話した、←でパス、Zで戻す。

## 5. 実装ログ
### v1 ステップ1: 質問データ
- `questions.js` に44枚を作成し、Node.js で件数やタグを検証した。

### v1 ステップ2: 画面
- 「重めを除く」スイッチだけを常時表示し、段階・出典は `<details>` に畳んだ。バッジは色だけに頼らず文字ラベルを付けた。
- つまずき
  - ボタンの文言が390px幅で折り返した → 「前の質問」に短縮した。
  - 初回表示で、スイッチがアニメーションの途中で描画された → 読み込み後にだけ `.is-ready` クラスでアニメーションを有効にした。
  - 日本語の改行が不自然だった → `word-break: auto-phrase` と `text-wrap` を指定した（対応ブラウザのみ有効）。

### v1 ステップ3: ロジック
- `app.js` を、純粋なロジック（フィルター・山札）と画面制御に分けた。前者は Node.js 単体でテストできる。
- シャッフルバッグ方式の山札（`createDeck`）: シャッフルした配列の末尾から引くので、1周するまで重複しない。山札を作り直した直後に、直前と同じカードが出ないよう入れ替える。
- つまずき: `questions.js` を `const QUESTIONS` と書いたら、`app.js` から参照できなかった。通常の `<script>` の `const` は `window` のプロパティにならないため → `var` に変更した。

### v2 ステップ1: 原典からの訳し直し
- 36問を英語原文から訳し直し、`set` 項目を追加した。テストで「36問は Set ごとに12問、段階と Set が一致する」ことを確認している。

### v2 ステップ2: カード画面（A・B・D・F）
- カードの状態を CSS クラスで表す。`state-top`（山札の上）→ `state-drawn`（手元・裏）→ `state-revealed`（表）。
- 位置は CSS 変数 `--y` で状態ごとに決め、ドラッグ中だけ JS が `transform` を直接書く。指を離したら inline の `transform` を消すと、CSS の transition で元の位置に戻る。
- 山札は `.deck-layer` を最大6枚重ねて描く。カードを引くと山札全体を下にずらして縮め（`.tucked`）、手元のカードの下から少しのぞかせる。
- カードの大きさは `min(88vw, 420px, (100dvh - 220px) / 1.56)`。画面の高さにも収まるように決めている。

### v2 ステップ3: スワイプと記録（C・H）
- `gesture.js`: Pointer Events でドラッグを追跡する。指を離したときに、直近100msの移動から速さを求める。
- 判定（`decideSwipe`）は純粋な関数にしてテストした。
  - 80px以上動かせば、速さに関係なく確定する。
  - 0.45px/ms以上の速さなら、28px以上で確定する。ただし動かした向きと勢いの向きが同じときだけ。
  - それ以外は元の位置に戻す。
- 山札の `peek()`（次のカードを引かずに見る）を追加した。裏面に次のカードの段階を出すため。
- つまずき
  - jsdom のテストで、ゆっくり50pxだけ動かしたのにカードが捨てられた。合成イベントが同じ時刻に発生し、速さが極端に大きく計算されていた → テストで `performance.now` を疑似時計に差し替え、ゆっくりした操作と素早いフリックを両方検証するようにした。
  - 2周目に入るとエラーが出た。シャッフル通知の関数 `toast` を定義し忘れていた → UIテストの「1周回す」ケースで発見して修正した。
  - jsdom の配列と Node.js の配列はプロトタイプが違い、`deepStrictEqual` が失敗した → JSON に通して比較した。
  - スワイプ中のスタンプが段階バッジに重なった（スクリーンショットで発見）→ 表示位置を下げた。

  - 設定・記録の検証（v1 の名前の読み替えを含む）、出典表示
  - スワイプ判定
- 画面の自動操作（jsdom、リポジトリには含めない）
  - 上スワイプで引く、タップでめくる、左右スワイプで話した／パス
  - 戻す（2種類）、ボタンだけの操作
  - 1周して全カードを1回ずつ見ることと、シャッフル通知
  - 記録シートと2回押しの消去、記録の保存と復元
